# WP-21: Trends loads summary data only

**Status:** Suggestion · **Priority:** P2 · **Depends on:** WP-12

## User task it protects

*Compare approaches.* Trends compares timing across games. It should open quickly without downloading every game's
full Move Explorer data.

## Basis

**Observed problem**
- Trends fetches all seven games' full JSON files in parallel (`trends.html:631-634`): about 5.75 MB raw (about
  0.47 MB gzipped), including Super Smash Bros. Ultimate 2.57 MB and Elden Ring 1.55 MB.
- It uses about 15 fields per move. Unused weight includes Super Smash Bros. Ultimate `clips` (524 KB) and `extra`
  (378 KB), `url` (167 KB and 162 KB in two games), and Elden Ring `weapons` (147 KB) and `parryable` (67 KB).
- **Scroll handling forces layout repeatedly.** Every scroll event schedules a new `requestAnimationFrame(spy)`
  without coalescing (`trends.html` around line 570); `spy()` reads every card's position, writes `aria-pressed` on
  every ruler key, then reads `offsetLeft` in `placePlayhead()`. The chart tooltip rewrites its `innerHTML` and
  measures on every pointer move, even over the same target.

**Assumptions**
- Trends' summaries change only when an importer runs, so they can be generated at import time.

## Proposed scope

1. Generate a slim `frame-data/trends.json` with only the fields Trends uses (or precomputed summaries) when frame
   data is imported, and load that instead of the seven game files.
2. Coalesce the scroll handler into one animation frame, or use an `IntersectionObserver` for the section spy.
3. Update the tooltip only when its target changes.

## Out of scope

- New charts or comparisons.

## Open questions

- `trends.json` is a new generated data file. Generate it in each importer, or in a separate script run before
  deployment? It must never go stale relative to the game files.

## Metric

- Trends bytes transferred on a cold load: about 5.75 MB raw → under 100 KB.
- Time to the first chart (WP-12 setup).
- Long tasks while scrolling Trends: baseline → none over 50 ms.

## Done when

- Every chart shows the same numbers as before.
- `trends.json` is regenerated by the documented import workflow (`frame-data/README.md`).
